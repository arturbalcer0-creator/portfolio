# Делегирование тяжёлой генерации в DeepSeek (через aider)

Мастер-настройка: как отдавать токеноёмкую генерацию в DeepSeek, а Claude оставлять
на ревью/фиксы. Рабочий конфиг лежит рядом — [`aider.conf.yml`](./aider.conf.yml).

## Когда это применять

**Только для КРУПНЫХ / шаблонных задач.** Экономия берётся с *генерации*: DeepSeek
пишет черновик дёшево, Claude лишь читает diff и правит. На мелких хирургических
правках выгоды нет — ревью всё равно стоит токенов Claude, а генерации почти нет.
Правило: файл/задача маленькие → делай напрямую в Claude; большой новый модуль,
много бойлерплейта, генерация с нуля → делегируй.

> На этом портфолио-проекте (≈1000 строк, файлы до ~120 строк) делегирование
> **не окупается** — конфиг вынесен сюда из корня именно поэтому. Реактивировать —
> когда появится реально большая задача.

## Предусловия

- **aider установлен**: `~/.local/bin/aider` (aider 0.86.2 на изолированном Python 3.12
  через `uv`; системный Python 3.9 слишком стар). Бинарник не в дефолтном PATH —
  вызывать полным путём.
- **`DEEPSEEK_API_KEY` в окружении *запущенной* сессии Claude Code.** Обычный
  `export` в уже запущенную сессию НЕ долетает — сессию надо стартовать из шелла,
  где ключ уже экспортирован (или задать ключ в env приложения).
- Проект — git-репозиторий (нужен для ревью diff'а).

## Как активировать

```bash
# 1. вернуть конфиг в корень проекта (aider ищет его там):
cp docs/aider.conf.yml .aider.conf.yml
# 2. убедиться, что ключ есть в сессии:
echo "$DEEPSEEK_API_KEY"   # должно быть непусто
```

## Как вызывать

```bash
~/.local/bin/aider --yes-always --no-stream --message "<описание задачи>" <файлы>
```

Затем: `git diff` → проверка (`tsc -b` / сборка) → правки или переформулировка →
оставить или откатить `git checkout -- .`. Для сложной логики — модель
`deepseek/deepseek-reasoner` (правится в конфиге).

## Содержимое конфига

`auto-commits: false` — правки aider остаются в рабочем дереве для ревью до коммита.
Модель по умолчанию — `deepseek/deepseek-chat`. Полный файл: [`aider.conf.yml`](./aider.conf.yml).
